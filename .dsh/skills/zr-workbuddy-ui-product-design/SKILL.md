# UI 产品设计（写码前置）

目标：在 **需求摘要 / 确认卡** 阶段就把界面预期说清楚，避免 Cursor 落地时「小学生式布局」。

> 本仓无 simplified 的 `propose_ui_design` / 配方库；设计结论写进 **requirement 摘要** 或对话，由 Cursor Local 在目标仓库实施。

## 何时读本 skill

- 用户要做/改 **登录、工作台、报表页、企业后台**，且强调专业/有设计感
- 用户提供 **参考截图 / 效果图**（可描述或附件）
- **纯后端 / 纯逻辑 / 非 UI 任务不要读**

## 能力栈（本架构下）

| 优先级 | 做什么 |
| --- | --- |
| 1 | 用户参考图 → 书面拆解布局（见 §2） |
| 2 | 无图 → 按项目 **现有页面风格** 延伸，不另起一套 |
| 3 | 读 **zr-workbuddy-ui-craft** 核对硬伤清单 |
| 4 | 把结论写入 requirement：**布局、色板、组件、禁止项** |
| 5 | 确认后才 `mes_code_dev_start` |

## 无参考图标准流程

1. 先看目标仓库是否已有同类页（侧栏+顶栏+表格报表等）→ **克隆其结构**  
2. 用 5～8 条 bullet 写 **界面规格**（见 §3 模板）  
3. 制造/MES/ERP 话术：偏专业、信息密度适中，禁止花哨营销页  
4. 将规格并入写码确认卡的 `requirement`  
5. 实施阶段 Cursor 读 craft skill 防硬伤

## 有参考图时

1. **先拆解再写码**，在 requirement 中写清：  
   - 左右/上下比例、是否有浮卡、主按钮颜色  
   - 字段列表、Logo/文案、顶栏页脚有无  
2. 要求 Cursor **1:1 对齐观感**，技术栈可不同  
3. 不确定的细节 **问用户一句**，勿发明参考图没有的设备/装饰  
4. 参考图只约束 **本轮目标页**，禁止扩散改其它页

## 界面规格模板（写入 requirement）

```text
【界面规格】
- 页面类型：（登录 / 工作台 / 列表报表 / 表单）
- 布局：（顶栏+侧栏+主区 / 全屏登录对分 / …）
- 主色与按钮：（高对比可点，勿假禁用灰）
- 关键区块：（KPI 卡 / 筛选栏 / 表格列 / 图表位）
- 路由与菜单：（例：/reports/employee-work-hours）
- 禁止：（勿改未点名页、勿 unsplash 乱配图、勿默认组件零主题交差）
```

## 设计底线

- 设计感 = **层级、对比、留白、统一控件**，不是堆特效  
- 禁止无关 random 图当行业视觉  
- 企业产品：**假禁用主按钮、改未授权页** = 不合格  
- UI 任务在 requirement 里点名 **目标 vue/路由文件**

## 与写码链路

1. **需求阶段**（本 skill + requirements skill）→ 摘要含界面规格  
2. **确认卡** → 用户核对  
3. **Cursor Local** → 读 craft + 项目现有代码实施  
4. **P0-1 不自动 commit** → 完成后汇报改动文件，提交等 P0-2

## 相关 Skill

- **zr-workbuddy-ui-craft** — 实施与验收硬伤清单  
- **zr-workbuddy-requirements** — 需求收集与保真  
- **zr-workbuddy-coding-impl** — 全栈 CRUD 同轮补 API
