# 企业级产品 UI 实施规范

面向中文企业软件（MES/ERP/报表后台）。  
验收：**无重大硬伤** + 与项目现有风格一致。

> 写进 **Cursor Local Job 的 requirement** 时可附「须遵守 zr-workbuddy-ui-craft」；  
> DSH Agent 在讨论阶段用 **zr-workbuddy-ui-product-design** 定规格，本 skill 管落地底线。

## 0. 优先级（不可颠倒）

1. **用户本轮点名的目标页** > 用户参考图 > **项目现有同类页** > 本 skill 默认  
2. **已完成且本轮未点名的页面：冻结** — 禁止「顺手统一风格」  
3. 有参考图：**观感不得另起一套**  
4. 无参考图：**延伸现有 AppLayout / 报表页结构**，禁止从零乱拼  
5. 非 UI 改造任务不要套用本 skill

## 1. 登录页：重大失败清单

| 失败 | 说明 |
| --- | --- |
| 页面两侧留白 | 登录被 `#app` max-width 框住；仅改登录时可最小修壳层 `width:100%` |
| 假禁用主按钮 | 灰紫/浅灰像 disabled → 必须高对比可点（深蓝/品牌色实心+白字） |
| 假分栏 | 参考是对分实面却做整屏深色+浮白卡；或相反 |
| 自造电子设备 | 无参考时禁止 CSS 画显示器/手机；有参考则须复刻 |
| 默认皮 | Element/Ant 零主题直接交差 |
| 改隔离页 | 只做登录别动首页；反之亦然 |

### 控件基线

- 输入高 40–44px，圆角 8–10px  
- Label **左对齐**在输入上方  
- 主按钮高 ≥44px；仅 loading/disabled 才变灰  
- focus 环可见；错误态清晰

## 2. 工作台 / 报表页：重大失败清单

- 登录后空白欢迎页无结构 → 失败  
- 缺顶栏或侧栏却称工作台 → 失败  
- 裸 `el-card` 零定制 KPI → 失败  
- 用户只要求「调侧栏宽/icon」却新建平行侧栏、改 App 壳 → **直接失败**  
- 把 MES 多图表看板换成极简壳 → 失败  

### 局部调整纪律

用户说「菜单栏宽度 / 折叠 / icon / 配色」等 **局部** 要求：

1. **只改** 目标 layout/侧栏相关文件  
2. **禁止** 新建平行侧栏、改路由壳、重写整页  
3. 未点名的 KPI/图表/顶栏 **一行不动**

合格骨架：顶栏 + 侧栏 + 欢迎区/筛选 + 表格或 KPI + 主工作区。

## 3. 有参考图落地

1. 书面拆解：比例、实色/浮卡、按钮色、字段与文案  
2. 再写代码；不确定问用户  
3. 参考图 **只指导本轮目标页**

## 4. 色板（无参考图默认）

- 深面：`#0B1220` / `#0F1B2D`  
- 浅面：`#FFFFFF` / `#F5F7FA`  
- 主按钮：`#1A5CFF` 或 `#1B4F72`  
- 禁止常态主按钮用 `#B8C0CC` 类死灰蓝

## 5. 业务 CRUD 页额外要求

**新建菜单/列表页** 且仓库已有 FastAPI 后端时，同轮须：

- 后端：路由 + model/schema（`/docs` 可见）  
- 前端：`api/*.js` 封装，禁止长期假数组  
- 路由 + 侧栏菜单入口  

纯样式微调、只改登录壳除外。

## 6. 交付自检（仅目标页）

- [ ] 主按钮常态明显可点？  
- [ ] 登录全屏时无多余留白？  
- [ ] 布局与参考/规格一致？  
- [ ] 未改禁止范围内页面？  
- [ ] 新业务页是否接了真实 API？  

P0-1 **不自动 commit**；完成后在 Job 同步文件列表中核对。
