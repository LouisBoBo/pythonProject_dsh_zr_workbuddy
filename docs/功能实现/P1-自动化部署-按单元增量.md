# P1 按插件增量部署

> feature id：`code-deploy` · 引擎包：`engine/app/code_deploy/`  
> 流程与 SSH 配置对齐 simplified「人触发预发部署」；**核心差异**：按 **部署单元（插件）** 增量同步，不是整仓 `frontend/dist+backend`。

## 产品流

1. 配置中心第 8 步开启 `code_deploy`，填 SSH（host/user/key/远端仓库根）  
2. 对话「部署到预发 / 部署上线」→ **系统自动判定**全量/增量（人只确认触发）  
   - 对比 `last_deploy.json` 上次成功 SHA → HEAD（含未提交变更）；探测远端是否为空  
   - **强制全量**：首次、基线失效、远端空、触及 scripts/依赖、未映射关键路径、单元过多等（不可改增量）  
   - **建议全量**：变更面较大（可改增量，自担漏发）  
   - **增量**：仅命中少量单元时自动全选，无需人挑插件  
3. 人点确认 → rsync；成功后写入 last deploy SHA  
4. **模型不执行 SSH**；工具 `mes_code_deploy_confirm` 须 `confirmed=true`

## 单元规则（灵活核心）

| 变更路径 | 单元 id | 动作 |
|----------|---------|------|
| `features/<id>/` | `feature:<id>` | 只同步该插件目录，不重启 |
| `engine/app/**` 等 | `engine` | 同步后 `engine.sh restart` |
| `plugins/mes-bridge|mes-runtime` | `bridge` | 同步后 `install bridge --restart` |
| `.dsh/skills/`、`scripts/` | skills / scripts | 仅同步 |
| `docs/**` 等 | （跳过） | 默认不部署 |

**例：** 只改了 `code-commit`、`code-dev` → 确认卡只有这两个；其它插件、引擎、bridge **不动**。

也可在 prepare/confirm 传 `unit_ids` 强制指定。

## 配置（界面核心项，仅本机 SSH）

对齐 simplified 设置页「自动化部署」主区，**不提供 GitHub Actions**（境外 Git / 连国内机用 SSH）：

| 界面字段 | 配置键 |
|----------|--------|
| 开启自动化部署 | `enabled` |
| 部署执行方式 | 固定 `local_ssh` |
| 默认分支 / tag | `default_ref` |
| 部署后访问地址（探活） | `health_url` |
| 本地项目路径 | `default_workspace` |
| 主机 / 用户 / 私钥路径 / 远端目录 / SSH 端口 | `ssh_*` |

环境白名单等有默认值，界面不展示。私钥只存本机路径；`config.yaml` 永不 rsync。

## API / CLI

- `GET /api/code-deploy/status`  
- `POST /api/code-deploy/prepare`  
- `POST /api/code-deploy/confirm`  
- `GET /api/code-deploy/jobs/{id}`  
- CLI：`code-deploy-status|prepare|confirm|job`

## 验收

- 只改两个 feature → Job 仅含这两个 unit，无 engine/bridge  
- 未点确认 → 远端无变化  
- feature 部署不触发 DSH 重启
