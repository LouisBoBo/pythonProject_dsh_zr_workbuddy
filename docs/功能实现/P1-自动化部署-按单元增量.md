# P1 按插件增量部署

> feature id：`code-deploy` · 引擎包：`engine/app/code_deploy/`  
> 流程与 SSH 配置对齐 simplified「人触发预发部署」；**核心差异**：按 **部署单元（插件）** 增量同步，不是整仓 `frontend/dist+backend`。

## 产品流

1. 配置中心第 8 步开启 `code_deploy`，填 SSH（host/user/key/远端仓库根）  
2. 对话「部署到预发 / 部署上线」→ **系统二元判定**全量 / 增量（人只确认；可把增量**升级**为全量）  
   - 对比 `last_deploy.json` 上次成功 SHA → HEAD（含未提交；已部署同内容脏文件忽略）  
   - **全量（锁定）**：首次、基线失效、远端空、触及 scripts/vendor/根依赖、未映射关键路径、单元≥6、scripts+engine/bridge 同改等 → 确认后同步**目录全部单元**，**禁止**改增量  
   - **增量**：其余情况 → 确认后只同步 **diff 命中单元**（自动全选）  
   - **禁止「建议全量」中间态**：判定结果只有全量或增量两种  
3. 人点确认 → rsync；成功后写入 last deploy SHA + 脏文件指纹  
4. **模型不执行 SSH**；工具 `mes_code_deploy_confirm` 须 `confirmed=true`

## 单元规则（灵活核心）

| 变更路径 | 单元 id | 动作 |
|----------|---------|------|
| `features/<id>/` | `feature:<id>` | 只同步该插件目录，不重启 |
| `engine/app/**` 等 | `engine` | 同步后 `engine.sh restart` |
| `plugins/mes-bridge|mes-runtime` | `bridge` | **仅同步文件**；默认不重启 DSH。仅当 `auto_restart_bridge=true` 且远端已有完整 DSH profile 才重装 |
| `.dsh/skills/`、`scripts/` | skills / scripts | 仅同步 |
| `docs/**` 等 | （跳过） | 默认不部署 |

**例：** 只改了 `code-commit`、`code-dev` → 确认卡只有这两个；其它插件、引擎、bridge **不动**。

确认执行以 `job.execution` 为准：全量=全部单元，增量=prepare 命中集（客户端不可随意瘦身漏发）。

## 配置（界面核心项，仅本机 SSH）

对齐 simplified 设置页「自动化部署」主区，**不提供 GitHub Actions**（境外 Git / 连国内机用 SSH）：

| 界面字段 | 配置键 |
|----------|--------|
| 开启自动化部署 | `enabled` |
| 部署执行方式 | 固定 `local_ssh` |
| 默认分支 / tag | `default_ref` |
| 部署后访问地址（探活） | `health_url` |
| 本地项目路径 | `default_workspace` |
| 主机 / 用户 / 私钥路径 / 远端目录 / SSH 端口 | `ssh_*` |

环境白名单等有默认值，界面不展示。私钥只存本机路径；`config.yaml` 永不 rsync。

## 共享机安全（必读）

- 远端引擎**固定独立端口**（默认 `8091`，可由 `health_url` / `remote_engine_port` 指定），**禁止默认 8000**（易与其它项目冲突）  
- 外网访问须经 nginx 反代（如 `8092 → 127.0.0.1:8091`）；`health_url` 填公网入口，不要填仅本机监听的端口  
- `engine.sh stop/restart` **只杀本应用 PID**（校验 cmdline/cwd）；端口被其它服务占用时**拒绝抢占**  
- `auto_restart_bridge` 默认 **false**：不同步重启整台 DSH，避免影响同机其它服务  
- 远端若无 `~/.dsh/profiles/web/package.json`，即使误开 `auto_restart_bridge` 也会**拒绝** install（防止造半残 `.dsh`）  
- `plugin.sh install` 同样要求 profile 已存在，否则直接退出  
- 远端使用独立 `.venv`，不污染系统 Python / 其它项目环境  

## 二元判定契约（成熟机制）

| 判定 | UI | 确认执行 |
|------|-----|----------|
| 全量（`force_full`） | 锁定「全量」，无增量选项 | 同步 `units_full`（目录全部单元） |
| 增量 | 默认增量；可升级全量 | 同步 `units_incremental`（prepare 命中集，忽略客户端瘦身） |

`prepare` 写入 `job.execution = { mode, unit_ids, locked }`；`confirm` 按 `resolve_confirm_mode` + `resolve_execution_plan` 执行，与卡片文案一致。

## 为何不会「部署过又强制全量」

- 成功部署后写入 `last_deploy.json`：`sha`（当时 HEAD）+ **脏文件内容指纹**  
- 再次准备时：与上次指纹相同的未提交文件**忽略**；`requirements.txt` / bridge 源码等只映射到 **engine/bridge 增量**  
- 仅 scripts/vendor/根 package.json/远端空/首次/未映射关键路径/单元≥6 等仍**强制全量**
