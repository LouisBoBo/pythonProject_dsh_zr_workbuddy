# P0-2 人触发提交功能实现

> feature id：`code-commit` · 引擎包：`engine/app/code_commit/`

## 产品流

1. 对话「提交代码」→ `code_commit_ui.kind=pick`（选本机 Git 目录 + **提交分支**）  
2. 「开始门禁审核」→ `POST /api/code-commit/start`（list + gate，可带 `work_branch`）  
3. 阻断（P0/P1）→ 仅展示 findings，无提交按钮；可点「用写码修复」或输入「修复这些问题」  
4. **修复闭环**：按阻断 Job 的 `workspace` + findings 路径生成写码确认卡 → 人确认 → Cursor 写码 → 同步本机  
5. **写码成功后自动打开提交选目录卡**（同工程预填）→ 再门禁 → 确认卡 → commit/push（**仍须人点确认，不自动 git**）  

### 提交分支默认规则（确认卡）

1. 仓库**当前分支**（非保护分支）  
2. 否则配置中心 `code_commit.work_branch`  
3. 都没有 → 提示用户手填；空分支不可开始门禁  

### 审码→修复→提交闭环

| 步骤 | 触发 | 行为 |
|------|------|------|
| 门禁阻断 | start 后 `can_commit=false` | 落盘 `blocked` Job（含 workspace / findings / files） |
| 发起修复 | 「修复这些问题」/ 阻断卡按钮 / `prepare-fix` | 读最近阻断 Job → `code_dev_ui` propose（`write_scope`=finding 路径） |
| 写码 | 人点写码确认卡 | `POST /api/code-dev/confirm`（可带 `write_scope`、`source_gate_job_id`）；**不自动 commit** |
| 再提交 | 「提交代码」 | 同一工程重新门禁；通过后 HITL 确认才 git |

模型**不得**代执行 git；工具 `mes_code_commit_confirm` 须 `confirmed=true`。

## 模块

| 文件 | 职责 |
|------|------|
| `config.py` | `code_commit:` enabled / workspace / work_branch / default_push 等 |
| `intent.py` | 「提交代码」/「修复这些问题」意图 |
| `git_ops.py` | dirty 列表、中文 message、工作分支、commit/push/rebase |
| `gate.py` | 敏感路径 + Skill 或正则；仅 P0/P1 影响 `can_commit` |
| `skill_review.py` | `llm_freeform` + `.dsh/skills/zr-workbuddy-commit-batch-review` |
| `store.py` | `data/code_commit/jobs/`；`latest_blocked_job` |
| `ops.py` | status / check / prepare / start_gate / confirm / `prepare_fix_from_gate` |
| `chat_bridge.py` | 聊天出 pick 卡或修复 propose；不自动跑门禁 / 写码 |

## API / CLI

- `GET /api/code-commit/status`  
- `POST /api/code-commit/check|prepare|start|confirm`（`work_branch` 可选）  
- `POST /api/code-commit/latest-blocked` · `prepare-fix`  
- `GET /api/code-commit/jobs/{id}`  
- CLI：`code-commit-status|check|prepare|start|confirm|job|latest-blocked|prepare-fix|push-retry`

## 配置中心

「提交车道」：`enabled`、`default_workspace`、`work_branch`、`default_push`（默认 true）。

## 验收要点

- 未开 feature / 未开车道 → 明确提示，不出确认卡  
- 选目录卡展示提交分支；改路径后自动刷新分支预览  
- 阻断后可「修复这些问题」→ 写码确认卡带正确工程与文件路径  
- 含 `.env` 的本批 → `can_commit=false`  
- 本批可含文档 / Skill（`.md`）、SPA `index.html`、`.gitignore` 等；样式/图片/日志仍排除；LLM 深审仍只读功能源码  
- 文件范围 = 写码同步池仍脏 **∪** 同仓库其它 Git 可提交脏文件（不只提交同步池那几个）  
- 确认前无新 commit；确认后工作分支提交，禁止 main/master  
- 不产出「代码审核汇总报告」全文
