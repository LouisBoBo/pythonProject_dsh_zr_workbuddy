# P0-1 删除菜单车道

> **状态**：已落地（与写码共用 `code-dev` feature / HITL / 四步流水线）  
> **配套**： [P0-1-本机写码功能实现.md](./P0-1-本机写码功能实现.md)  
> **安全**：路径门禁见 [企业级安全加固方案.md](../安全/企业级安全加固方案.md) 删除车道小节

---

## 1. 一句话

用户说「某某菜单删除某某子项」→ 工具卡确认 → Cursor **只读定位**出删除清单 → **引擎**在本机工程删文件并修补菜单/路由/`main.py` 注册 → 结论四段式由引擎按**过程清单 + 真实落盘**汇总（不以 Cursor 自称的结论为准）。

---

## 2. 与「写码」的异同

| 维度 | 删除车道 | 写码车道（暂缓对齐） |
|------|----------|----------------------|
| 入口 | 同：`mes_code_dev_begin` → 卡确认 → nonce | 同 |
| 流水线 UI | 同：需求理解 → 沙箱 → 写码/定位 → 同步 | 同 |
| Cursor 角色 | **只读**定位（`delete_mode=cursor_plan`） | 在沙箱内改码 |
| 过程区正文 | Cursor 真实对话框（`_LiveProcess` + `cursor_only`） | Cursor 流式正文（未强制同一套 LiveProcess） |
| 结论 / 改动文件 | **引擎** `build_engine_delete_delivery`：过程清单顺序 ∩ 实际删除 + 修补文件 | 暂信 Cursor「说明方案」文案 |
| 验尸 | `verify_delete_on_target`（菜单/路由/孤儿页） | 同步校验为主 |
| Vite | `force=True` 软重启更积极 | 软热更 |

产品约定：**删除体验已打磨；写码结论对齐后补，不阻塞删除交付。**

## 3. 机制要点

### 3.1 意图

`brief.is_delete_intent` + `delete_verify.extract_delete_features`（叶子菜单名，如「综合看板」「设备看板」）。

### 3.2 过程清单 → 批准删除

1. Cursor 终稿解析：`parse_delete_plan_from_text`（`## 删除清单`）。  
2. `validate_delete_plan`：  
   - 引擎功能白名单（`_FEATURE_ORPHAN_FILES`）必批（若存在且在 write_scope）；  
   - 过程清单中的专属 `views/*.vue`（高置信）、`frontend/src/api/*`、`backend/app/routers/*` 可批；  
   - **共用壳拒绝整删**（`warehouse.py` / `auth.py` / `request.js` / `schemas.py` / `main.py` 等）；  
   - **路径穿越拒绝**（`..` / `resolve` 后须落在工程根内）。  
3. `reconcile_delete_artifacts`：物理删除 + 修补 `AppLayout` / `router` + 按已删 `routers/*.py` 卸掉 `main.py` 的 import/`include_router`。

### 3.3 结论四段式

模板：结论 / 改动文件 / 行为约定 / 验收。  
`align_delivery_files_with_process`：按过程出现顺序排列真实删除，再并入修补/同步文件。  
`flush_delivery(..., force=True)`：一次替换到位，避免「卡顿后突然出现」。

### 3.4 write_scope

删除类诉求自动带上 `frontend/src/views/`（含 board/kanban）、`backend/app/routers/`、`backend/app/main.py` 等。  
**禁止**再扩成整棵 `backend/app/`（防同步面过大）。

## 5. 验收清单

- [ ] 「看板管理菜单删除 X 看板子项」出卡 → 确认后过程为 Cursor 定位对话，非引擎套话。  
- [ ] 结论「改动文件」含过程删除清单中**实际删掉**的页/API/路由，以及菜单/路由/`main.py` 修补。  
- [ ] 共用 `warehouse.js` / `schemas.py` 等不被整文件删除。  
- [ ] 过程夹带 `frontend/../../…` 不得批准。  
- [ ] 不出现「本轮运行失败 reading prepare」（见 [宿主与运维排障](../宿主与运维排障/dsh-tools双实例与prepare报错.md)）。

## 6. 配置

`engine/config/config.yaml` → `code_dev`（示例见 `config.example.yaml`）：

- `delete_mode`（默认 `cursor_plan`）  
- `delete_plan_timeout_sec` / 流式延迟等  

密钥仍只进本机 `config.yaml`，勿写入 feature 或本文。
