# WorkBuddy 企业级安全加固方案

> **状态**：P0 硬门禁已落地并完成绕过修补（UI 签发头、关闭 code-dev-start、path 不经公开 issue）；P1～P2 待实施  
> **依据**：架构铁律（`AGENTS.md` §0、`.cursor/rules/workbuddy-ops-standard.mdc`）+ 2026-09 写码/审码/提交通路复核  
> **原则**：加固控制面，**不推翻**单 Bridge + `features/`；引擎默认仍只绑回环；不另造与回环约定冲突的「业务自建公网 Token」除非单独立项企业接入层。

---

## 0. 一句话

当前架构**未偏**；企业级缺口主要在：**人确认可被 Agent 伪造**、**本机变异接口缺 CSRF/票据**、**审码可被绝对路径绕过选目录**。按下列 P0→P2 收口到可审计、可验收。

---

## 1. 威胁模型（企业级默认）

| 角色 / 场景 | 假设 | 要防什么 |
|---|---|---|
| 本机开发者 | 可信操作者 | 误操作、Agent 越权代确认、日志泄密 |
| 同机其它进程 / 浏览器页 | 半可信 | 对本机 `:8000` 的 CSRF / 任意 Origin 调 confirm/config |
| Agent（LLM） | **不可信执行体** | 撒谎 `confirmed=true`、乱传路径、扫盘后外送 |
| 远端（若未来暴露引擎） | 不可信网络 | **本方案默认不支持**；须企业反向代理 + SSO，禁止裸绑 `0.0.0.0` |
| 供应链 | feature zip / Skill | G3 校验；禁止任意生态包进引擎功能页 |

**明确不在本阶段范围**

- 多租户云端 SaaS 隔离  
- 把引擎改成公网多用户服务（须另立项）  
- 删除 Bridge / 合并单进程「图省事」

## 2. 现状缺口（对照企业控制）

| ID | 严重度 | 缺口 | 现状 | 企业期望 |
|---|---|---|---|---|
| H1 | **高** | 软 HITL | feature 只看 `confirmed=true`；`POST …/confirm` 无「人点过卡」证明 | 引擎校验 UI 签发、短时、一次性 nonce |
| H2 | **高** | 本机 CSRF / 任意本机 Origin | CORS regex 允许任意本机端口；变异接口无票据 | Origin 收紧 + 变异接口要 nonce/session |
| H3 | **高** | 审码路径绕过 | Agent 可传 `local_path` 直跑 | 主路径强制 path_ticket；裸路径仅 CLI 运维或关闸 |
| M1 | 中 | Job SSE 可读 | job_id 可知即可订 | 短时 job token；进度脱敏 |
| M2 | 中 | 空 write_scope 整仓同步 | 已有 shell 接线强制同步，空 scope 仍宽 | 企业开关 + 确认卡明示范围 |
| M3 | 中 | 配置中心 PUT | 本机可改 LLM Key 等 | 与 H2 同批：变异要同源/票据 |
| L1 | 低 | 审计轨迹 | 分散日志 | 统一 audit 事件（谁、何时、workspace、job） |

路径穿越 / 沙箱逃逸：当前实现已有防护，**P0 不重做**，回归测试锁死。

---

## 3. 架构约束（加固时禁止踩铁律）

1. 控制逻辑落在 **`engine/`**（校验 nonce、票据、审计）；feature 只传票据、不实现安全真相。  
2. UI 签发落在 **bridge client / 引擎 SPA**（人点击处），**不**焊进 `host/packages` 内核。  
3. 不新增业务正式 Cordis 包；不删 Bridge。  
4. 密钥仍只进 `config.yaml`；不在 feature / README 写 Key。  
5. 默认绑定 `127.0.0.1`；企业对外暴露 = **独立「企业接入」立项**（反向代理 + IdP），不是改 runtime host 了事。

## 4. 目标控制（企业级能力清单）

### C1. 硬 HITL（Human-in-the-Loop）

```text
用户点击确认卡
    → UI 向引擎 POST /api/hitl/issue  （或 confirm 内嵌签发）
    → 引擎返回 nonce（TTL≤5min，单次使用，绑定 workspace+动作类型）
    → 仅带合法 nonce 的 confirm 才能开工
    → Agent 工具不再接受「口头 confirmed=true」作为充分条件
      （可保留工具，但必须传入 UI 回写的 nonce；无 nonce 一律拒绝）
```

覆盖车道：`code-dev` / `code-commit` / `code-deploy`（及未来一切改盘/推远端）。

### C2. 本机变异面收敛

- CORS：开发期可保留本机 regex；**变异方法**额外校验：  
  - `Origin`/`Referer` ∈ 允许列表（3080、引擎自身、可配置扩展），或  
  - 带有效 hitl/session 票据。  
- `PUT /api/config`、所有 `*/confirm`、deploy 执行：同一策略。  
- 只读探活 / 健康检查可维持宽松。

### C3. 路径与读盘门禁

- 审码 / 写码 workspace：  
  - **主路径**：选目录 → `path_ticket`（绑定绝对路径规范化结果 + TTL）。  
  - Agent `local_path` 直跑：默认 **拒绝** 或仅当 `config.code_review.allow_agent_absolute_path=true`（企业默认 false）。  
- 保持现有 `validate_review_root` 黑名单；票据校验在其之上。

### C4. 出站与日志脱敏

- SSE / job 快照：禁止出现 `api_key`、`token`、`Authorization`、私钥 PEM。  
- `live_text` 截断 + 简单红线正则。  
- 审计日志写：`actor=ui|agent|cli`、动作、workspace 哈希或路径、job_id、结果。

### C5. 同步范围企业开关

- `code_dev.require_explicit_write_scope`（默认 true）：空 scope 不得整仓同步。  
- 确认卡必须展示将同步的目录/模块摘要；deferred 非空时完成态保持醒目警告（已有则锁定回归）。

## 5. 分阶段实施

### P0 — 硬门禁（建议 1～2 个迭代，阻断级）

| # | 项 | 落点 | 验收 |
|---|---|---|---|
| P0-1 | HITL nonce 签发与校验 | `engine/app/hitl/` + confirm 入口 | 无 nonce 的 confirm → 400；nonce 复用 → 400；过期 → 400 |
| P0-2 | 工具卡只传 nonce | `features/code-{dev,commit,deploy}` + bridge/引擎卡 | Agent 仅 `confirmed=true` 无法开工 |
| P0-3 | 审码 path_ticket | `code_review` + 选目录卡 | 默认拒绝裸 `local_path` 开跑（企业关闸可测） |
| P0-4 | 变异接口 Origin/票据 | `main.py` 中间件或依赖 | 异源本机页无法静默 confirm（用测试页验证） |
| P0-5 | 回归：沙箱路径不逃逸 | 现有 sync 单测/脚本 | 含 `..`、symlink 出根均失败 |

**P0 完成定义（DoD）**：在 DSH 会话中诱导 Agent「直接 confirmed 开工」必须失败；只有点击确认卡成功。

### P1 — 可观测与范围（企业审计）

| # | 项 | 验收 |
|---|---|---|
| P1-1 | audit 事件落盘（JSONL 或引擎 data） | 一次写码可追溯 issue→confirm→job 终态 |
| P1-2 | SSE/进度脱敏 | 注入假 Key 的进度文本被打码 |
| P1-3 | job 订阅 token（可选短密） | 不知 token 无法订他人 job（同机枚举难度上升） |
| P1-4 | `require_explicit_write_scope` | 配置 true 时空 scope confirm 失败 |

### P2 — 企业接入（可选立项）

| # | 项 | 说明 |
|---|---|---|
| P2-1 | 反向代理 + OIDC/LDAP | 仅当引擎必须非回环暴露时；应用内仍不发明业务 Token 头 |
| P2-2 | 远端部署审计与双人复核 | 与 G2 增量部署联动 |
| P2-3 | feature 安装签名/哈希允许列表 | 强化 G3 供应链 |

P2 **不得**借机把业务焊进 `host/` 或删除 Bridge。

## 6. 建议数据契约（实现草图）

```json
{
  "nonce": "htl_…",
  "action": "code-dev.confirm",
  "workspace": "/abs/path",
  "exp": 1730000000,
  "jti": "一次性 id"
}
```

- 存储：引擎内存 + 可选 `engine/data/hitl_nonces.json`（进程重启失效可接受；企业可改 Redis 另议）。  
- 签发：仅 UI（工具卡 / 引擎 SPA）；**不**经 Agent 工具签发。  
- CLI 运维通道：`code-dev-confirm` 可要求 `--nonce` 或仅本机交互 TTY 确认（二选一写进实现说明）。

## 7. 测试与验收矩阵

| 用例 | 期望 |
|---|---|
| 点击确认卡 → 正常写码 | 成功；audit 有记录 |
| Agent `mes_code_dev_confirm confirmed=true` 无 nonce | 失败 |
| 重放同一 nonce | 第二次失败 |
| 篡改 workspace 但沿用旧 nonce | 失败（绑定校验） |
| 其它 Origin 的浏览器 fetch confirm | 失败 |
| 审码不经选目录、只传 `/etc` 或家目录敏感路径 | 失败 |
| symlink 逃出 workspace 同步 | 失败 |
| 进度流含 `sk-` 形态密钥 | 脱敏或不出现 |

自动化：优先加在 `scripts/test.sh zr-workbuddy` 可跑的引擎单测；UI 用一条手工检查表即可。

## 10. 一句话结论

**架构保持 DSH 铁律；企业级把「人确认」「路径」「本机变异面」从口头约定升级为引擎可验证控制。**  
P0 未完成前，产品上仍视为「本机可信 + Agent 软约束」——可开发，不可按等保/审计口径宣称「硬 HITL 已达标」。
