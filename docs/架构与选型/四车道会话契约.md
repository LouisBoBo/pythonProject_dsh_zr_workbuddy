# 四车道会话契约（隔离 · 冻结 · 刷新可恢复）

> **状态**：契约定稿（2026-09-10）——**先守契约，再改代码**  
> **目的**：写码 / 审码 / 提交 / 部署四条车道 **会话状态互不串台**；已验收行为 **禁止顺手改**；刷新后 **本卡进度可恢复**。  
> **配合**：`AGENTS.md` §0、`.cursor/rules/workbuddy-ops-standard.mdc`、`docs/安全/企业级安全加固方案.md`  
> **单车道细则**：仍以各 `docs/功能实现/P0-*` / `P1-*` 为准；本文只钉 **跨车道会话边界**。

---

## 0. 一句话

**四车道各自有引擎包、feature、工具卡、Job 与 localStorage 前缀；修 A 不得改 B；定好的交互与持久化字段不得因「顺手」被剥空或回表单。**

## 1. 四车道身份（禁止混写）

| 车道 | feature id | 工具卡入口（举例） | 引擎包 | HTTP 前缀 | Job / 数据目录 |
|------|------------|-------------------|--------|-----------|-----------------|
| **写码** | `code-dev` | `mes_code_dev_begin` | `engine/app/code_dev/` | `/api/code-dev/*` | `engine/data/local_dev/jobs/`（`ldj-*`） |
| **审码** | `code-review` | `mes_code_review_begin` | `engine/app/code_review/` | `/api/code-review/*` | 审码会话/报告落盘（勿与写码 Job 混用） |
| **提交** | `code-commit` | `mes_code_commit_begin` | `engine/app/code_commit/` | `/api/code-commit/*` | `engine/data/code_commit/jobs/`（`cc-*`） |

**唯一常驻壳**：`plugins/mes-bridge`（`client.js` 里各车道卡片并存，但 **逻辑与持久化命名空间必须分开**）。  
**禁止**：为修提交去改写码 SSE / `live_text` 路由；为修写码去清提交 `wb-cc-*`；把四车道合成一张「万能卡」。

### 1.1 允许的跨车道联动（仅产品闭环，不是共享状态）

| 允许 | 怎么走 | 禁止 |
|------|--------|------|
| 提交门禁阻断 → 写码修复 | 提交卡出「修复」→ **新开**写码 HITL（独立 `callId` / 新 Job） | 共用一张卡的 phase、共用一个 localStorage key |
| 写码完成 → 用户再说「提交代码」 | **新开**提交 begin | 写码完成态自动变成提交选目录卡 |
| 部署引用引擎探活 | 只读引擎健康/入口 URL | 部署卡读写写码 `streamText` |

## 2. 会话身份（刷新恢复的硬键）

聊天壳里每张工具卡的稳定身份来自 DSH：

1. **`callId`**（`props.callId` / `block.callId`）——**主键**。无 `callId` 不得认领任何完成态。  
2. **`sessionId`**（会话线程）——辅助分桶。  
3. **引擎 `job_id`**（`ldj-*` / `cc-*` / …）——算数真相；有则双写 Job 快照。

### 2.1 localStorage 命名空间（禁止交叉）

| 车道 | 卡级 key 前缀 | Job 快照前缀 | UI 版本常量（示例） |
|------|---------------|---------------|-------------------|
| 写码 | `wb-cd-card:` | `wb-cd-job:` | `CD_UI_REV`（如 `2026-09-10o-cd-contract`） |
| 提交 | `wb-cc-card:` | `wb-cc-job:` | `CC_UI_REV`（如 `2026-09-10o-cc-contract`） |
| 审码 | `wb-cr-card:` | `wb-cr-job:`（可选） | `CR_UI_REV`（如 `2026-09-10o-cr-session`） |
| 部署 | `wb-cdp-card:` | （卡级即可） | `CDP_UI_REV`（如 `2026-09-10o-cdp-session`） |

**规则**：

- 前缀 **不得复用**；禁止「写码卡读 `wb-cc-*`」。  
- key 必须带 **`callId`**（推荐 `wb-*-card:{sessionId}:{callId}` + 别名 `wb-*-card:call:{callId}`）。  
- **禁止**用仅 `session` / `anon` 共享键存 `done` / `running`（否则新 begin 吞上一张卡）。  
- 完成态 **禁止删除**过程正文 / 终稿 / 提交详情字段；只允许截断上限与按年龄整键淘汰。

### 2.2 恢复 vs 新开（四车道同一语义）

| 情况 | 行为 |
|------|------|
| 本卡 `callId` 已绑定 `jobId`（或已落盘 `done`） | **恢复**完成态 / 进行中态；**不要**因工具 meta 仍是 `*-pick` 就回表单 |
| 新开 `mes_*_begin`（新 `callId`） | **必须**停在 HITL 起点（选目录 / 确认前）；**禁止**吃上一张卡的 `done` |
| 工具 meta 长期为 `pick` | **不表示**「永远未开工」；是否回表单只看 **本 callId 是否已有进度** |
| 「重新选择」 | 只清 **本卡** callId 对应键；不得清其它 call / 其它车道 |

## 3. 冻结清单（定好的东西禁止乱改）

未单独开需求、未改本文并 bump 对应 `*_UI_REV` 前，**禁止**改动下列已验收行为：

### 3.1 写码（`code-dev`）

| 冻结项 | 含义 |
|--------|------|
| HITL 开工 | 须 UI 签发 nonce；禁止聊天一句直接 `start` |
| 完成态展示 | 步骤条 + 过程正文 + 结论/改动文件；刷新后过程正文不得空壳只留结论 |
| 过程通道 | 引擎 `live_text` = 过程；`delivery_text` = 终稿；**禁止**把 `live_text` 再整段路由成终稿而剥空过程 |
| 持久化 | 完成态保留 `streamText` / `deliveryText`；空正文不得覆盖已有正文 |
| 隔离 | 新 `mes_code_dev_begin` 不得恢复他人 `done` |

### 3.2 提交（`code-commit`）

| 冻结项 | 含义 |
|--------|------|
| 流程顺序 | 选目录 → 勾选文件 → 门禁 → 确认 → commit/push |
| 成功卡信息 | 至少：项目/路径、分支、Commit、推送状态、说明、本批文件列表 |
| 刷新 | 已成功提交的 **本卡** 刷新后仍为完成态，不得回「选目录」 |
| 新 begin | 新「提交代码」必须是新选目录卡，不串旧完成态 |
| 模型不代 git | 无 nonce / 无人确认不得 commit |

### 3.3 审码（`code-review`）

| 冻结项 | 含义 |
|--------|------|
| 入口 | 「审代码」走 `mes_code_review_begin`，禁止默认 Bash/git diff 冒充审码卡 |
| 与提交门禁 | 提交批审 ≠ 全仓审码报告；两套 UI / 两套 API |

### 3.4 部署（`code-deploy`）

| 冻结项 | 含义 |
|--------|------|
| 人确认 | `code-deploy.confirm` + nonce |
| 验收 | 成败认引擎探活 / 入口，不认「是否重启 DSH」 |

### 3.5 全车道安全（与铁律并行）

- 引擎只绑回环；密钥只在 `config.yaml`。  
- 写盘 / 提交 / 部署：HITL nonce 引擎可验证。  
- 路径：选目录票或白名单，禁止裸绝对路径当主路径。

## 4. 改代码门禁（Agent / 人必须先过）

改四车道相关代码前，自检：

```text
□ 本次只动哪一条车道？（写码 / 审码 / 提交 / 部署 四选一）
□ 是否触及冻结清单？若是：是否已更新本文 + bump 该车道 *_UI_REV？
□ 是否改了其它车道的 persist / SSE / finish / hydrate？→ 禁止，拆 PR / 拆任务
□ 是否用空 payload 覆盖 done？（streamText / commitDetail 等）→ 禁止
□ 新 begin（新 callId）是否仍会吞旧 done？→ 必须有隔离单测或手工清单
□ bridge 改动后是否重启宿主使 client.js 生效？（仅改 feature 热插拔不够）
```

### 4.1 推荐改动面

| 要改什么 | 允许动 | 默认禁止动 |
|----------|--------|------------|
| 写码过程/刷新 | `code_dev/*`、`CodeDevBeginCard`、`wb-cd-*`、写码单测 | `CodeCommit*`、`wb-cc-*`、`code_commit/*` |
| 提交成功/刷新 | `code_commit/*`、`CodeCommitBeginCard`、`wb-cc-*`、提交单测 | 写码 `applyStreamPayload` / `live_text` 路由 |
| 审码路由 | `code_review/*`、审码卡、`index.js` 路由表 | 写码/提交 persist |
| 共享 CSS / `ensureCss` | 仅加选择器，不改既有车道语义 | 借机改四个 Card 的 phase 机 |

### 4.2 单测与版本号

| 车道 | 建议单测 | 卡上可见版本 |
|------|----------|--------------|
| 写码 | `engine/tests/test_cd_persist_isolation.mjs` | `CD_UI_REV` |
| 提交 | `engine/tests/test_cc_persist_isolation.mjs` | `CC_UI_REV` |
| 审码 | `engine/tests/test_cr_persist_isolation.mjs` | `CR_UI_REV` |
| 四车道总检 | `engine/tests/test_four_lane_session_contract.mjs` | 各 `*_UI_REV` 同批 |
| 部署 | （总检含 `CDP_UI_REV` / `wb-cdp-card:`） | `CDP_UI_REV` |

刷新验收：**以卡上版本号为准**；版本未变说明 bridge 未加载新 `client.js`，先 `plugin.sh … install bridge --restart`，再谈业务 bug。

## 5. 已知坑（契约为何写成这样）

| 坑 | 后果 | 契约对策 |
|----|------|----------|
| 工具 meta 一直是 `*-pick` | 误判「必须回表单」 | 恢复只认 callId 绑定进度，不认 meta 字面 |
| 完成时删 `streamText` / 空串覆盖 | 刷新后只剩结论或空白 | 合并保留；Job 快照双写 |
| session/anon 共享 done | 新 begin 直接出完成态 | 有 callId 只写 call 专属键 |
| 同一 PR 改写码+提交 | 「修提交写码又坏」 | 一车道一任务；交叉改必须拆开 |
| 只改仓内文件未重启 bridge | 用户仍看旧 UI | 改 `client.js` 必须重启宿主 |
