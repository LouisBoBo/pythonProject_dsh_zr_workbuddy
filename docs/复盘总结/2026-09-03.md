## 2. 今日做了什么

### 2.1 P1 部署主路径

- 引擎包 `engine/app/code_deploy/`：prepare / confirm / policy / ssh_sync / units / diff_map / store  
- feature `code-deploy`：`mes_code_deploy_*`  
- 确认卡：环境 / 主机 / 远端 / SHA 对比 / 命中单元与动作说明  
- 成功卡：对齐提交成功卡样式（访问地址、远端、环境、方式、动作、基线 SHA、单元列表）

### 2.2 共享机踩坑与加固

| 现象 | 根因 | 处理 |
|------|------|------|
| 引擎重启超时 | 系统 Python 无依赖；后缺 `python-multipart` | 远端独立 `.venv` + `requirements.txt` 补依赖 |
| 怕误伤已有服务 | 默认 8000 已被 graphrag；旧 stop 按端口杀 | `engine.sh` 只认本应用 PID（cmdline/cwd）；远端固定 8091 |
| bridge 重装失败 | 远端无 `~/.dsh/profiles/web/package.json` | `auto_restart_bridge` 默认 false；无 profile 拒绝 install；清理半残 `.dsh` |
| `http://…:8091/` 外网不可达 | 引擎只绑 `127.0.0.1` | nginx `8092` 反代；`health_url` 改为公网 8092 |
| 已部署仍强制全量 | 脏 `requirements.txt` 当脚手架锁全仓；只记 SHA 不记脏文件内容 | 依赖走 engine 增量；`last_deploy` 增脏文件指纹；同内容忽略 |
| 增量卡仍写「重启 DSH」 | `action_hint` 与真实行为不一致 | bridge 默认「只同步文件，不重启 DSH」；UI 按配置 enrich |

### 2.3 全量 / 增量：成熟二元机制

- **去掉「建议全量」中间态**  
- **全量（`force_full`）**：锁定 → 同步目录全部单元，禁止改增量  
- **增量**：只同步 prepare 命中单元；可升级全量；confirm 忽略客户端随意瘦身  
- `prepare` 写入 `job.execution = { mode, unit_ids, locked }`；`confirm` 按计划执行  

强制全量条件（摘要）：首次 / 基线失效 / 远端空 / scripts·vendor·根依赖 / 未映射关键路径 / 命中单元≥6 / scripts+engine|bridge 同改。

### 2.4 关键结论（可带走）

1. **共享机部署 = 本应用隔离**：独立端口 + 独立 venv + 默认不碰 DSH/其它项目。  
2. **对外入口 ≠ 引擎监听地址**：回环给引擎，公网走 nginx；`health_url` 填公网。  
3. **判定文案必须等于执行**：卡片 hint / confirm / ssh_sync 三处一致，否则用户不信任。  
4. **基线要记「部署了什么」**：仅 HEAD SHA 不够，脏文件要内容指纹。  
5. **二元策略比「建议全量」更稳**：只有 full / incremental，执行集写死在 `execution`。
