## 目标与结果

| 目标 | 结果 |
| --- | --- |
| 部署成功卡对齐提交成功卡 | **P**：短摘要 + 结构化键值 + 本批单元/同步路径 |
| 人只触发部署，不猜「要不要重启 DSH」 | **P**：`auto_restart_bridge` 默认 **true**；含 bridge 则 install + 后台重启远端 DSH |
| 回执可在服务器核对单次范围 | **P**：scp 写 `last_deploy_receipt.json`；文档标明 find 宽窗口≠单次 |

## 做了什么

1. **成功卡**：`cdpSuccessCardHtml`（bridge 面板 + 引擎 SPA）对齐提交卡；confirm 返回 `code_deploy_ui.kind=success` 强制挂载。  
2. **回执**：修复 scp 写入；文档强调回执/`job_id` 为准，`find -cmin` 会混多次部署。  
3. **产品纠偏**：自动化部署默认含 bridge 即重启远端 DSH（人不必再手动）；SSH 侧改为 install 后 **nohup** `restart-dsh.sh`，避免前台 `exec dsh` 挂死。  
4. **配置**：`config.yaml` / `config.example.yaml` / 代码默认改为 `auto_restart_bridge: true`。  
5. **文档**：重写/同步 `P1-自动化部署-按单元增量.md`（原则、收尾表、流程图、风险、验收）。  
6. **附带**：提交 push-retry 成功后展示完整提交成功卡。

| 成功后只有短摘要+绿条 | DSH 内存旧 bridge / 未挂 success UI | success kind + restart-dsh；文档区分热插拔 vs 面板壳 |

| `plugin.sh … --restart` 挂 SSH | `restart-dsh.sh` 前台 `exec dsh` | 远端后台 nohup |
