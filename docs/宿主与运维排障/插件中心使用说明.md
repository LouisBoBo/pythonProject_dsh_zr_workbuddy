# 插件中心使用说明

> 摘自 DeepSeek Harness 官方口径（本仓不放 Studio 源码）。生态插件必须在跑起来的 Studio / `dsh web` 里装，不能走引擎功能页 zip。

## 公司插件 + 官方市场（同一页）

`dshmarket` 只能认一份 `DSHM_REGISTRY_URL`。WorkBuddy 启动时把**公司目录**和**官方 awesome-dsh-plugin 目录**合成一份，再指过去：

- **公司插件永远可装：** 公司站拉不到就用上次缓存，再没有用仓库种子；官方站挂了不会把公司插件弄没。本仓 seed 会**叠加**进公司目录（远端尚未上架的包如 `@zhongruan/dsh-knowledge` 仍可见）。
- **官方每天最多同步一次**（成功后 24 小时内不再拉；失败后 6 小时内不重试）。
- **公司插件排在发现页最前**（含默认「按下载量」排序），并有「中软」分类可筛。
- 安装包仍走原来的 `@zhongruan` 私有 npm；官方包走 npm / GitHub。

开发壳启动后目录是本机回环 `http://127.0.0.1:18731/plugins.json`（桌面包默认 `18732`）。  

**【LOCKED】** 置空 `DSHM_REGISTRY_URL=` **不再**恢复官方市场（会被忽略）。  
唯一破窗（仅调试，禁止发版默认）：`WORKBUDDY_ALLOW_OFFICIAL_MARKET=1`。  
自定义非空 URL 仍可作为合并结果覆盖。

### 强制约束：重新打包 / 重启不得弄丢私有插件

权威规则：`.cursor/rules/workbuddy-company-market.mdc`。  
验收：`python3 scripts/lib/verify_company_dsh_market.py`（`host.sh verify` 已挂）。

| 现象 | 常见原因 |
|---|---|
| 插件市场还能开，但没有「中软」、首页全是高下载社区包 | 宿主进程**没有** `DSHM_REGISTRY_URL`，静默用了官方目录 |
| 刚 `restart-web` 又没了 | 用了裸 `dsh web`，或 shell 里 `export DSHM_REGISTRY_URL=` |
| 点了「更新插件市场」后又没了 | 旧进程无 `DSHM`；现已写入 `$DSH_HOME/.env`，再启动应自带合并目录 |
| 公司站挂了 / 新包未上架 | 应仍见 seed 里的 `@zhongruan/*`；若没有=合并/seed 被打包漏掉 |

持久化：`apply_company_dsh_market` 会把 `DSHM_REGISTRY_URL` 写进 `$DSH_HOME/.env`（`# --- workbuddy-company-market ---` 块）。`dsh` 的 `loadLayeredEnv` 会读 harness home `.env`（`DSHM_` 不在 bootstrap 禁写列表）。  

**【LOCKED】** 无破窗时禁止清除该块；`host.sh` 无合并结果则 **拒绝启动**。  
破窗：`WORKBUDDY_ALLOW_OFFICIAL_MARKET=1`（仅调试）。

**禁止**把「官方市场能刷列表」当成公司插件还在。发版前 verify 必须过。

公司站若以后要自己对外提供合并结果，可在那台机器 cron：

```bash
python3 scripts/lib/merge_company_dsh_market.py write --out /path/to/plugins.json
```

## 安装完成后发生什么

用户在插件中心点击「安装」并确认后，会下载确定版本、完成校验、写入当前 Profile、重启 Harness Host，并重新连接页面。只有插件声明的 Host、客户端或 Skill 运行证据都出现后，操作才会显示完成。

需要区分三个状态：

- **已安装：** 插件包已经进入当前 Profile。
- **已启用：** 插件 Bundle 已加入当前运行组合。
- **运行中：** Host 重启后的真实运行证据已经出现，此时才能认为插件可以使用。

## 安装后从哪里使用

不同插件没有统一的「打开」方式，应先在插件详情或「已安装」区域查看它贡献的能力：

| 能力类型 | 使用方式 |
|---|---|
| 工具、Host 或 Agent 能力 | 回到对话，直接描述要完成的任务。Agent 会在需要时调用插件提供的工具；这类插件不一定新增页面或按钮。 |
| Skill Pack | 在对话中直接描述匹配任务，让 Agent 自动选择；也可以输入 `/skill-name` 明确调用详情中显示的 Skill 名称。 |
| 客户端界面 | 使用插件自己贡献的入口，常见位置是左侧导航、独立页面、设置或会话区域。Host 重连后该入口才会出现。 |
| MCP 或外部服务 | 回到对话使用它提供的工具；如果插件要求账号、密钥或服务地址，先从「已安装」进入原有插件设置完成配置。 |
| 模型提供方 | 完成插件要求的凭证配置后，在模型选择入口选择对应模型。 |

插件详情中的能力、权限和说明决定它的具体用法。插件中心负责安装与激活，不会为所有第三方插件虚构一个相同的使用入口。

## 最短验证步骤

1. 安装插件并等待操作显示完成。
2. 打开「已安装」，确认状态为「已启用」和「运行中」。
3. 查看详情中的能力类型、运行条目、客户端模块或 Skill 名称。
4. 按上表进入对应入口完成一次真实任务。
5. 完整退出并重新打开（桌面或 `dsh web`），再执行同一任务，确认能力仍然可用。

## 已安装但不能使用时

依次检查：

1. 插件是否被停用，或因版本不兼容被自动保持停用。
2. 「已安装」中的运行状态是否为「运行中」，不能只看包是否存在。
3. 插件是否要求在设置中补充账号、密钥或其他配置。
4. 高级运行清单中是否出现详情声明的 Loader、客户端模块或 Skill。
5. 如果操作显示失败或需要恢复，先完成恢复，再重新安装或启用。

普通浏览器开发页面只能模拟上述状态。真实安装、Host 重启、MCP、文件系统和插件能力使用必须在 DeepSeek Harness Studio（本仓即 `scripts/host.sh up` 拉起的 `:3081`，或桌面一体包）中完成。
