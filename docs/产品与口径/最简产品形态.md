# 最简产品形态（推荐日常口径）

> **状态**：2026-09-07 修订（纠正：真正的第三方 DSH 插件不能走 `features/` zip）  
> **一句话**：业务、热插拔、改哪发哪走引擎；**能在 DSH 市场里一键安装的第三方插件必须走 Studio 插件中心**（这就是要 host 的原因）。两条通道不要混。

## 1. 两种「插件」不是一回事

| 种类 | 例子 | 怎么装 | 为什么 |
|------|------|--------|--------|
| **WorkBuddy 功能包** | `mes-ask`、`code-dev`、按本仓契约写的薄包装 | 引擎功能插件页 / `install-feature` → `features/` | 禁止 npm、必须 `index.js`+`manifest.json`、算数在引擎。**任意 DSH 生态包会校验失败**——这是有意的，不是漏做。 |
| **DSH 第三方生态插件** | 插件中心上的 Bundle / Skill / MCP / 带 UI 的 Cordis 包 | **Harness Studio 插件中心**（安装进当前 Profile，重启 Host 后运行） | 它们是 npm 包、要 Loader、要权限与兼容性检查。引擎 zip 通道**装不了**，已验证。 |

铁律仍在：`AGENTS.md` 禁止把任意生态 zip 硬塞进引擎功能页。  
要装真正的第三方，**必须有跑起来的 Studio（插件中心）**，所以才引入 `host/`。

官方也写了：浏览器开发页只能**模拟**安装；真实安装、Host 重启、MCP、文件系统必须在 **DeepSeek Harness Studio** 里完成（见 `host/PLUGIN_CENTER_USAGE.md`）。

## 2. 最简主流用法（不研究 DSH 怎么实现）

把 Studio 当**已经做好的安装器**用，本仓只接线，不改它的内核。

```text
DeepSeek Harness Studio（插件中心 + 聊天）
        │  ~/.dsh/link + profile 挂上 mes-bridge
        ▼
WorkBuddy bridge + features + engine
        │
        ├─ 业务、热插拔自有功能、改哪发哪  →  引擎 :8000
        └─ 装/启停/卸 DSH 生态插件      →  Studio 插件中心
```

日常：

```bash
# 业务引擎（自有功能 + 增量部署）
scripts/engine.sh zr-workbuddy ensure          # :8000

# 把 WorkBuddy 接到 Studio（只需做一次或换机器时）
scripts/host.sh wire
scripts/host.sh verify

# 打开 Studio（插件中心在这里，不要用引擎页冒充）
# 桌面端：官方 / 本仓打的 Studio
# 或已接线的 dsh web → 侧栏「插件」
```

在插件中心里：搜索 → 确认安装 → 等「已启用 / 运行中」→ 回对话用。  
不要把同一个 zip 丢进引擎「功能插件」页。

自有能力热插拔、改哪发哪，仍只动 `features/` 和 `code_deploy`，与生态插件分轨。

## 3. `host/` 源码树怎么养（尽量省事）

你需要的是 **Studio 这个产品（插件中心）**，不是天天改那 147 万行。

| 做法 | 说明 |
|------|------|
| **推荐** | 钉一个 Studio 发行版当运行时；本仓 `host/` 能启动就冻结，**不要从 Downloads 反复覆盖** |
| **接线** | 只维护 `scripts/host.sh wire` + bridge，业务永不写进 `host/packages` |
| **升级** | 等有明确理由（插件中心坏了、官方强制升）再换一个 tag，当发版做，不要跟 weekly rc |
| **不要** | 用引擎 `install-feature` 代替插件中心；不要为了「装第三方」去学 Cordis 实现 |

同仓留 `host/` 的意义：能跑与本机一致的 Studio、能对照插件中心源码、桌面包可内嵌 Host。  
**维护面是「钉版本 + 接线」，不是「当自己的 IDE 仓库合上游」。**  
怎么升版本（命令与验收）：[host维护与更新.md](../宿主与运维排障/host维护与更新.md)。

## 4. 验收怎么拆

| 要验什么 | 看哪 |
|----------|------|
| 查数 / 写码 / 审码 / 提交 / 按单元部署 | 引擎网页、探活 |
| 开关 `mes-ask` 等自有功能 | 引擎功能插件页 / `plugin.sh` |
| **装上一个真正的 DSH 第三方插件并能用** | Studio 插件中心：已安装 + 已启用 + 运行中，再做一次真实任务 |

两条都要，才覆盖你说的「基础业务 + 热插拔 + 第三方 + 改哪发哪」。
