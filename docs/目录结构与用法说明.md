# 这仓库是干啥的、怎么用

一句话：**ZR-WorkBuddy 工作助手**（仓库名 DSH-ZR-WorkBuddy）——独立引擎网页 + 热插拔功能 + 按单元增量部署。  

**三大核心目标**（立项北星，详细技术落地见 [三大核心目标落地方案.md](./三大核心目标落地方案.md)）：

1. 用 DSH 的热插拔写法做能力（只进 `features/`）  
2. 按单元增量部署「改哪发哪」  
3. 在 WorkBuddy 里安装第三方能力（同样进 `features/`）  

工程写法借鉴 DSH 插件范式；**业务验收以引擎网页 / API 为准**（装不装 Harness 窗口不作为核心验收）。

---

## 先记住三句话

```bash
# 1. 把业务引擎拉起来（没开就开，开了就跳过）
scripts/engine.sh zr-workbuddy ensure

# 2. 看看现在开了哪些功能
scripts/plugin.sh --app zr-workbuddy features

# 3. 开/关某个功能（热插拔，约 1s）
scripts/plugin.sh --app zr-workbuddy enable mes-ask
scripts/plugin.sh --app zr-workbuddy disable mes-ask
# 写码示例：scripts/plugin.sh --app zr-workbuddy enable code-dev
```

浏览器：

- 引擎 SPA（配置中心 / 对话 / 功能插件）：`http://127.0.0.1:8000/`（端口以 `runtime.yaml` 为准）  
- 引擎接口文档：`http://127.0.0.1:8000/docs`  
- 本机若另开了 Harness：常见 `http://127.0.0.1:3080`（**非**三大目标验收项）

## 用大白话拆分层

可以想成一家店：

| 角色 | 仓库里对应啥 | 人话 |
|---|---|---|
| 店面（员工入口） | `engine/` SPA + HTTP | 浏览器打开 WorkBuddy 网页、对话、配置、功能插件页 |
| 店里总管 | `plugins/mes-bridge` | 热插拔宿主（唯一常驻 Cordis 包）；把 features 插拔上 |
| 具体工种 | `features/*` | 真正干活的能力；**第三方也装这里**（G3） |
| 后厨 | `engine/app` | Python 算数、部署 SSH、写码 Job；端口见 runtime.yaml |
| AI 工作手册 | `.dsh/skills/` | DSH Agent 的 Skill（教怎么选工具、怎么收集写码需求） |
| 工具箱 | `scripts/` | 启动、装卸、测试用的命令 |
| 备件柜 | `vendor/` | 从 DSH 拷来的依赖，别乱换版本 |

**日常加功能：只动 `features/`，不用重启 DSH。**  
**只有改总管（bridge）或第一次接线：才需要重启 DSH。**

## 业务应用长什么样（`apps/zr-workbuddy/`）

```text
zr-workbuddy/          # 脚本 --app 名；产品是 ZR-WorkBuddy
├── VERSION            # 版本号，发版时改一下
├── engine/            # 后厨：业务引擎
├── plugins/           # 总管 + 小工具库
│   ├── mes-bridge/    # 挂到 DSH 上的那一个
│   └── mes-runtime/   # 帮总管调后厨的库（不是独立插件）
└── features/          # 可热插拔的功能（重点）
    ├── mes-ask/       # 自然语言查数 → 工具名 mes_ask
    ├── mes-config/    # 测连接 / LLM → mes_config、mes_status
    ├── mes-pcb/       # PCB 工艺专家 → mes_pcb
    ├── code-dev/      # 本机 Cursor 写码 → mes_code_dev_*
    └── code-review/   # 本机目录审码 → mes_code_review_*
```

引擎里与写码相关的后厨代码在 `engine/app/code_dev/`（Job、沙箱、确认校验等），  
**不是** feature，改 Python 后需 `engine.sh restart`。

本机审码后厨在 `engine/app/code_review/`（`local_files` 直读 + Viprasol Skill LLM + `enrich` 补种 + SSE 流式终稿）。

### `features/` —— 你最常改的地方

每个功能一个文件夹，里面通常就两个文件：

- `manifest.json`：叫啥、干啥用（给人看的说明）
- `index.js`：真正注册工具的代码  

加新功能：

```bash
scripts/plugin.sh --app zr-workbuddy new 报表 "随便写个说明"
# 然后去改：apps/zr-workbuddy/features/报表/index.js
# 默认已经打开了，过大概 1 秒 DSH 里就能用，不用重启
# 引擎 SPA「功能插件」页会自动出现这一项（扫 features/，不用改管理页代码）
```

改**已经打开**的功能的 `index.js`：不用重启 DSH。bridge 会看文件修改时间，  
自动先卸掉再装上（大约一个轮询周期，约 1 秒）。等不及可以 disable→enable。

关掉 / 再打开：

```bash
scripts/plugin.sh --app zr-workbuddy disable 报表
scripts/plugin.sh --app zr-workbuddy enable 报表
```

谁在听这个开关？总管 `mes-bridge` 盯着  
`engine/data/plugins.json`（**启停真相源**，写路径统一带文件锁）。  
改这个文件就会装上或卸掉；引擎 HTTP 只是方便脚本写入的同一份文件，引擎挂了也能靠脚本/本地写回退改状态。

> **热插拔范围（G1）**：`features/` 业务能力。引擎 SPA 随 **engine 单元**发布；bridge 是加载器，不是员工主入口。  
> Cordis 侧靠 `ctx.plugin` / `fiber.dispose`，不要自造另一套插件生命周期。

### `.dsh/skills/` —— DSH Agent 工作手册（与 feature 并列）

```text
.dsh/skills/
├── zr-workbuddy-routing/           # 总路由：查数 / PCB / 写码 / 配置
├── zr-workbuddy-code-dev/          # 写码 HITL、工具顺序
├── zr-workbuddy-requirements/      # 需求收集、brief 保真
├── zr-workbuddy-ui-product-design/ # UI 定规格（登录/报表页等）
├── zr-workbuddy-ui-craft/          # UI 实施硬伤清单
├── zr-workbuddy-coding-impl/       # Cursor 改码短清单
├── zr-workbuddy-repo-bootstrap/    # 陌生仓库先摸底
└── zr-workbuddy-code-review/       # 本机审码（非 Git）
```

**人话**：Skill 教 DSH 里的 Agent「什么时候、按什么流程说话」；feature 提供「能调用的工具」。  
Skill 放 `.dsh/skills/`，**不用**重启 DSH 装 Cordis 包；与 `features/` 热插拔互不替代。

- DSH workspace 指向本仓库时，侧边栏 **技能中心** 可看到上述 Skill  
- 写码链路：requirements →（UI 时 ui-*）→ 确认卡 → `mes_code_dev_*`  
- 详细机制见 `docs/功能实现/P0-1-本机写码功能实现.md`

### `plugins/mes-bridge` —— 总管（很少改）

- 提供 `mesEngine`，把 features 热插拔上去（加载器）  
- 顺带挂了聊天小面板（网页右下角那种）  
- 第一次装、或者你改了 bridge / mes-runtime 代码，才需要：

```bash
scripts/plugin.sh --app zr-workbuddy install bridge --restart
```

### `engine/` —— 后厨

一直跑着一个本地服务（默认 `127.0.0.1:8000`，**只绑回环、无自造鉴权**；勿改成对公网监听）。  
启停统一用 `scripts/engine.sh`（Node 侧 ensure 也走这条，不直接 spawn uvicorn）。

常用文件：

| 你想干啥 | 改 / 看哪个 |
|---|---|
| 改端口 | `engine/config/runtime.yaml`，然后 `scripts/engine.sh zr-workbuddy restart` |
| 填业务连接、DeepSeek 密钥 | 复制 `config.example.yaml` → `config.yaml` 再填（**别提交到 git**） |
| 开本机写码（Cursor） | 引擎 SPA **配置中心 → 写码车道** 勾选开启、填 Key；或改 `config.yaml` 的 `code_dev` |
| 改「用户问这句话该查啥 / 是否写码」 | `engine/app/nl_engine.py`、`engine/app/code_dev/intent.py` |
| 改写码需求讨论、确认校验 | `engine/app/code_dev/`（`discuss.py`、`brief.py`、`chat_bridge.py` 等） |
| 改怎么查业务数据、怎么画图 | `mes_analyzer.py` / `analyzer.py` 等 |
| 开本机审码 | 配置中心 **审码车道** + `engine/app/code_review/` |
| 命令行试审码 | `python3 engine_cli.py code-review-status` |
| 命令行试一嘴 | `cd engine && python3 engine_cli.py ask "今日再制品工单"` |

后厨怎么起停：

```bash
scripts/engine.sh zr-workbuddy ensure   # 推荐：没有就后台拉起
scripts/engine.sh zr-workbuddy status   # 看看活着没
scripts/engine.sh zr-workbuddy stop
scripts/engine.sh zr-workbuddy restart
```

改完 Python 代码要 **重启引擎**（不用重启 DSH）。

| 你想干啥 | 敲啥 |
|---|---|
| 保证后厨在跑 | `scripts/engine.sh zr-workbuddy ensure` |
| 看功能开没开 | `scripts/plugin.sh --app zr-workbuddy features` |

## 本机 DSH 那边（不在仓库里）

装应用时脚本会弄这些东西（知道有就行）：

- `~/.dsh/link/DSH-ZR-WorkBuddy` → 指回这个仓库（免得路径写死本机目录）  
- `~/.dsh/profiles/web` → DSH 真正加载插件的地方（里面应该主要是 mes-bridge）  
- `~/.dsh/profiles/web.bak/` → 改 profile 前自动备份，搞砸了能 restore

## 按场景走一遍

**每天来写点东西 / 问数**

```bash
scripts/engine.sh zr-workbuddy ensure
# 打开 3080，聊天里用 mes_ask，或点面板
```

**本机写码（P0-1，人先确认再改代码）**

```bash
scripts/engine.sh zr-workbuddy ensure
scripts/plugin.sh --app zr-workbuddy enable code-dev   # 若未开
```

1. 浏览器打开引擎 SPA → **配置中心 → 写码车道**：勾选开启、填 Cursor API Key、保存  
2. 点「测试写码就绪」或 CLI：`python3 engine_cli.py code-dev-status`  
3. 在引擎 SPA 对话里发写码诉求，并带上**本机工程绝对路径**，例如：  
   `在 /Users/你/项目 开发：员工工时报表页面`  
4. 按提示：**思考 → 需求选项卡 → 写码确认卡 → 点确认** → 看进度卡  
5. 完成后看同步文件列表；**不会自动 git commit**

Agent 工具名：`mes_code_dev_status` / `check` / `start`（须 `confirmed=true`）/ `job` / `cancel`。

**本机审码（P0-3，对话触发）**

```bash
scripts/engine.sh zr-workbuddy ensure
scripts/plugin.sh --app zr-workbuddy enable code-review
```

1. 配置中心 → **审码车道** 开启 + LLM 已配置  
2. 在 **工作助手对话** 中说：`审核代码`（或带路径）→ 确认卡选目录 →「开始审核」  
3. 看进度卡 + **终稿逐行流式**「代码审核汇总报告」；报告含 LLM 条数 / 规则补种 / `fresh_id`  
4. 或 DSH Agent：`mes_code_review_run` / `mes_code_review_report`  

详见 `docs/功能实现/P0-3-本机审码功能实现.md`。

**加一个新工具（不重启 DSH）**

```bash
scripts/plugin.sh --app zr-workbuddy new xxx "说明"
# 编辑 features/xxx/index.js
```

**改查数 / 写码逻辑（Python）**

```bash
# 改完 engine/app 里的文件（查数 或 code_dev/）
scripts/engine.sh zr-workbuddy restart
# 写码单测：cd apps/zr-workbuddy/engine && python3 -m unittest tests.test_code_dev -v
```

**改面板或总管代码**

```bash
scripts/plugin.sh --app zr-workbuddy install bridge --restart
```

**换引擎端口**

```bash
# 改 engine/config/runtime.yaml 里的 port
scripts/engine.sh zr-workbuddy restart
```

## 别踩的坑

1. **别再往 DSH profile 里堆一堆正式插件。** 功能请放 `features/`；Skill 请放 `.dsh/skills/`。  
2. **`config.yaml` 有密钥，别提交。** 只提交 `config.example.yaml`。  
3. **feature 的 `index.js` 尽量别自己 import 一堆包**——通过 `ctx.get('mesEngine')` 用总管给的能力。  
4. **引擎没起来，查数 / 写码一定挂。** 先 `ensure`，再聊。  
5. **改 Python 要重启引擎；改已启用 feature 的 JS 由 bridge 按 mtime 热重载；改 bridge / mes-runtime 才重启 DSH。**  
6. **写码聊天路径不会自动开工。** 必须点确认卡或 Agent `mes_code_dev_start` 且 `confirmed=true`。  
7. **写码与查数别混。** 「做报表页面」走 code-dev；「查今日产量」走 mes_ask。  
8. **写码默认关闭。** 配置中心未开 `code_dev.enabled` 时，start 会拒绝。
